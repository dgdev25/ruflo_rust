# Codebase Audit — 2026-08-14

Focus: can this codebase become an always-on appliance with active (resident) agents?
Security detail: dedicated `/security-audit-skill` is a thin `npx ruflo security scan` wrapper in this repo. Findings below come from source review of appliance, daemon, swarm, MCP HTTP, and budget paths. Not a full CVE/dependency sweep.

Verdict (source-bound): **not as shipped.** The repo is a native **foundation and Node-parity CLI facade**. It is not an appliance host. Command names exist (`appliance`, `daemon`, `lifecycle`, MCP `agent_spawn`). The processes, image, supervisor, and spend gates that an always-on agent appliance needs do not.

Locked decisions that this audit does not reopen:
- ADR-0005: no JavaScript runtime in the native binary.
- ADR-0008: swarm workers are one-shot `claude`/`codex` subprocesses, not resident in-process agents.
- ADR-0006: remote MCP stays disabled unless authenticated.
- ADR-0010: zero Node runtime dependency.
- PRD REQ-013: appliance is Wave 3, only after consumer-driven evidence.

- [ ] **[4] [P0] Architecture** — `ruflo-runtime` is an in-memory ID map, not a supervisor
      `Runtime::ephemeral()` stores handles in a `Mutex<HashMap>`. `AgentState` has only `Spawned`. Production CLI and MCP do not construct `Runtime`.
      There is no process table, heartbeat, restart policy, or durable agent identity.
      📍 `src/crates/ruflo-runtime/src/lib.rs:67-86`, `src/crates/ruflo-runtime/src/agent.rs:34-36`

- [ ] **[5] [P1] Security** — `appliance extract` copies unconfined paths
      Destination is `{target}/{path}` from the manifest with no canonicalization. Source is the live workspace path, not bytes inside the RVFA.
      A crafted manifest can read or write outside the extract directory.
      📍 `src/crates/ruflo-cli/src/appliance.rs:211-224`

- [ ] **[6] [P1] Bug** — Swarm concurrent budget is checked, then N workers are forked
      `LIMIT_CONCURRENT` is 1. `run_swarm` can still record N permits and spawn N `claude`/`codex` processes. Daemon `trigger` ticks do not book the ledger.
      Always-on spend cannot be enforced from this split control plane.
      📍 `src/crates/ruflo-cli/src/swarm_exec.rs:21-93`, `src/crates/ruflo-cli/src/daemon.rs:595-614`

- [ ] **[7] [P1] Security** — ADR-0008 worktree isolation is not implemented
      Swarm workers all use the shared project `cwd`. There is no `--worktree` path, cgroup, or namespace.
      Concurrent writers on one checkout is the default if this becomes a host.
      📍 `src/crates/ruflo-cli/src/swarm_exec.rs:488`

- [ ] **[8] [P1] Architecture** — Four disjoint state authorities
      Durable memory is SQLite (`ruflo-storage`). Lifecycle writes `.swarm/*.json`. Services write `.claude-flow/services/*.json`. Runtime is process-local.
      An appliance cannot answer “which agents are alive?” from one source.
      📍 `src/crates/ruflo-storage/src/lib.rs`, `src/crates/ruflo-cli/src/lifecycle.rs:611-633`, `src/crates/ruflo-cli/src/services.rs:48-72`

- [ ] **[9] [P1] Architecture** — MCP `agent_spawn` does not create a process
      The handler returns `agent-{role}` / `status: spawned`. It does not call runtime, lifecycle, or `Command`.
      MCP clients can believe an agent is live when nothing is running.
      📍 `src/crates/ruflo-mcp/src/dispatcher.rs:312-324`

- [ ] **[10] [P2] Security** — `daemon stop --all` SIGTERMs any `/proc` cmdline containing `ruflo` and `daemon`
      After skipping ancestors, any matching process is killed, including `ruflo daemon status` or a test runner whose argv contains those words.
      Unsafe on a long-lived host.
      📍 `src/crates/ruflo-cli/src/daemon.rs:435-467`

- [ ] **[11] [P2] Bug** — Swarm budget ledger fail-open vs daemon fail-closed
      `read_budget_ledger()` treats a malformed `ai-budget.json` as empty and continues spawning. `daemon.rs::read_ledger()` errors so it cannot reset the breaker.
      A corrupt file silently reopens spend.
      📍 `src/crates/ruflo-cli/src/swarm_exec.rs:114-125`, `src/crates/ruflo-cli/src/daemon.rs:163-174`

- [ ] **[12] [P2] Bug** — `headless::execute` can hang on full stdout/stderr pipes
      It pipes both streams and polls `try_wait` without draining. A chatty child fills the OS pipe and blocks until timeout. `daemon trigger` uses this path. `swarm_exec` already drains.
      📍 `src/crates/ruflo-cli/src/services.rs:434-476`

- [ ] **[13] [P2] Security** — Unwired catalog handler executes `bash -c`
      `tools_catalog::terminal` runs the caller command after a substring ban-list. Production `Dispatcher` does not register this handler today.
      Wiring the catalog into an appliance would add unsandboxed shell execution.
      📍 `src/crates/ruflo-mcp/src/tools_catalog.rs:252-264`

- [ ] **[14] [P2] Architecture** — `process` and `daemon` do not share a live process identity
      `process daemon-start` degrades. `daemon.rs` uses `daemon-state.json` and never writes a PID. Two operator surfaces, no supervisor identity.
      📍 `src/crates/ruflo-cli/src/process_cmd.rs:101`, `src/crates/ruflo-cli/src/daemon.rs:363-381`

## Refactoring

- [ ] **[15] [P1] Refactor** — `services.rs` is a 2878-line Node-parity facade
      Many modules only mutate JSON and claim behavioral parity. The file exceeds the 500-line rule by a large margin.
      Split proven job pieces (`headless` one-shot, budget files, autostart strings) from unused theater. Do not grow this file into the appliance process.
      📍 `src/crates/ruflo-cli/src/services.rs:1`

- [ ] **[16] [P2] Refactor** — Duplicate AI-budget implementations
      `daemon.rs` and `swarm_exec.rs` each implement ledger path, prune, and lock semantics, with opposite malformed-file policy.
      One fail-closed module, used by every spawn path, same behavior, less code.
      📍 `src/crates/ruflo-cli/src/daemon.rs:82-214`, `src/crates/ruflo-cli/src/swarm_exec.rs:19-143`

- [ ] **[17] [P2] Refactor** — CLI dispatch files are oversized
      `command.rs` is 2668 lines, `lib.rs` is 2436 lines. Same 500-line rule.
      Dispatch tables can shrink without changing argv contracts.
      📍 `src/crates/ruflo-cli/src/command.rs`, `src/crates/ruflo-cli/src/lib.rs`

## Features

- [ ] **[18] [P0] Gap** — No supervisor that can keep the process up
      `install-supervisor` writes a crontab snippet and tells the user to install it. It does not install systemd/launchd. The generated ExecStart target does not stay running.
      An appliance needs PID 1 or a unit with a blocking serve loop, health, and restart policy.
      📍 `src/crates/ruflo-cli/src/daemon.rs:783-793`

- [ ] **[19] [P1] Gap** — RVFA is not a bootable image
      `build` writes pretty-printed JSON hashes of a few local config files. Profiles claim ~15 MB / ~500 MB / ~4 GB footprints that are never produced. `run` always exits 1. No Dockerfile or OCI image exists.
      This cannot be shipped as a self-contained appliance.
      📍 `src/crates/ruflo-cli/src/appliance.rs:64-99,231-246`

- [ ] **[20] [P1] Gap** — Agents are JSON records or one-shot CLIs, not residents
      `lifecycle::spawn_agent` writes `.swarm/agents/<id>.json` with status `idle`. Hive-mind appends idle workers; `--claude` runs one `claude -p` and exits. Autopilot stores flags in `autopilot.json` and does not loop.
      Nothing survives CLI exit or reboot.
      📍 `src/crates/ruflo-cli/src/lifecycle.rs:611-633`, `src/crates/ruflo-cli/src/hive_mind.rs:222-269`, `src/crates/ruflo-cli/src/autopilot.rs:19-54`

- [ ] **[21] [P1] Gap** — Health does not observe live processes
      `agent_health` maps a stored status string. `repo_supervisor` probes git/build/disk and claims a daemon loop that `start()` never calls. No `/health` HTTP endpoint.
      An appliance orchestrator cannot tell running from recorded.
      📍 `src/crates/ruflo-cli/src/lifecycle.rs:825`, `src/crates/ruflo-cli/src/repo_supervisor.rs:5-16`

- [ ] **[22] [P1] Gap** — Unified hard spend control on every spawn path
      Budget pause/show/resume exists. Swarm checks a file (fail-open). Hive and MCP spawn do not share the same reservation. USD budget in services is unused by those paths.
      Always-on agents without one fail-closed limiter will burn tokens.
      📍 `src/crates/ruflo-cli/src/daemon.rs:650-778`, `src/crates/ruflo-cli/src/swarm_exec.rs:31-95`

- [ ] **[23] [P2] Gap** — REQ-013 appliance evidence is missing
      The PRD defers appliance until consumer-driven compatibility evidence exists. The capability manifest does not list an appliance capability. Claim remains `partial-native-parity`.
      Shipping “appliance product” from this repo would violate the documented gate.
      📍 `docs/PRD.md:40`, `docs/capabilities/native-capability-manifest.json:1-15`

- [ ] **[24] [P2] Feature** — New appliance host process, not more CLI theater
      Add a long-lived native serve binary (stdio MCP + optional authenticated HTTP) that owns a job queue, PID/heartbeat table, and crash/backoff. Reuse `ruflo-storage`, `ruflo-mcp` dispatcher, `ruflo-config` policy, `ruflo-actions`. Keep ADR-0008 workers as one-shot jobs.
      Completing `appliance.rs` / `daemon start` as Node ports will not produce a host.
      📍 `src/crates/ruflo-mcp/src/dispatcher.rs:275-309`, `src/crates/ruflo-cli/src/swarm_exec.rs:1-8`

- [ ] **[25] [P3] Feature** — Real image + signed updates after the host exists
      OCI (or a real RVFA) that packs the host binary, config, and optional models. Ed25519 verify-before-run. Fail-closed checksums.
      Only useful after [18] and [24].
      📍 `src/crates/ruflo-cli/src/appliance.rs`, `src/crates/ruflo-cli/src/appliance_advanced.rs`

## What is reusable (do not throw away)

| Piece | Why it matters for an appliance |
|---|---|
| Single native binary, no Node | Fits a small image and systemd/container host |
| `ruflo-storage` + `ruflo-memory` | Durable SQLite + RVF |
| `ruflo-mcp` 4 typed tools + `tool.unsupported` | Honest remote surface (ADR-0006 HTTP is feature-gated + HMAC identity) |
| `ruflo-config` ToolPolicy + capability manifest | Allow/deny before execution |
| `ruflo-actions` declarative allowlist | No JS plugins (ADR-0005) |
| `swarm_exec` one-shot workers + timeout + env strip | Real job runner, not a resident agent |
| Daemon budget pause/resume (fail-closed read) | Start of a spend brake |

## What “active agents” can mean here

1. **Resident workers waiting on a queue** (supervisor + jobs). Feasible. Matches ADR-0008 if each job is a bounded `claude`/`codex` subprocess.
2. **Always-running LLM sessions** (Node daemon style: interval workers that spawn `claude` every N minutes). The Node product already warns this burns tokens (12 h TTL). This repo does not implement that loop. Implementing it as “always on” without a hard budget is a cost and safety failure.
3. **In-process agent runtime inside the binary.** Rejected by ADR-0005/0008. Do not do this.

Recommended product shape: **(1)**, not (2) or (3).
