# Codebase Audit — 2026-08-09

Focus: full Rust-to-Node parity audit, including a real NAPI-RS addon.

Security detail: the dedicated security-audit skill was unavailable in this
session; the credential persistence finding below is a targeted source review.
The clean, fresh-target `cargo test --workspace` suite passed, but its success
does not establish untested Node contract parity.

## Bugs

- [ ] **[1] [P0] Security** — Native auth writes credentials to a project file
      `auth login --token-stdin` persists bearer tokens, and failed OAuth exchange falls back to persisting the authorization code.
      Project-local credentials can be committed, shared, or replayed; this differs from the Node keychain-backed contract.
      📍 `src/crates/ruflo-cli/src/auth.rs:15-17`, `166-245`

- [ ] **[2] [P0] CLI contract** — Unsupported subcommands return exit 0 with overview text
      Recognized command families fall through to `NativeOverview` rather than returning a deterministic unsupported error.
      Shell and agent automation can treat unimplemented operations as completed successfully.
      📍 `src/crates/ruflo-cli/src/command.rs:1973-2021`, `src/crates/ruflo-cli/src/lib.rs:475-668`

- [ ] **[3] [P0] MCP contract** — Catalog tools are advertised as supported without real schemas or handlers
      The Rust server exposes 279 names with empty object schemas and generic JSON CRUD for many requests.
      MCP clients receive a success-shaped response for operations whose Node validation, side effects, and result contracts are absent.
      📍 `src/crates/ruflo-mcp/src/dispatcher.rs:163-208`, `src/crates/ruflo-mcp/src/tools_catalog.rs:23-162`

- [ ] **[4] [P0] Release evidence** — The checked parity checklist contradicts the living compatibility ledger
      `REMAINING_COMMAND_CONVERSIONS.md` marks complete work that `command-parity.md` still identifies as pending fixtures and end-to-end evidence.
      The repository can make a false “53/53/full parity” claim despite only proving family dispatch or overview output.
      📍 `docs/REMAINING_COMMAND_CONVERSIONS.md:5-82`, `docs/compatibility/command-parity.md:1-80`

- [ ] **[5] [P1] Provider contract** — `providers test` treats key presence as connectivity
      Rust does not call provider endpoints or distinguish invalid credentials, timeouts, and response errors.
      It can report a revoked key as healthy, unlike Node's bounded connectivity check.
      📍 `src/crates/ruflo-cli/src/providers.rs:231-270`, `/mnt/datadisk/dev/ruflo/v3/@claude-flow/cli/src/commands/providers.ts:65-129`

- [ ] **[6] [P1] Persistence contract** — Migration tests do not use populated Node state
      The fixture is empty and tests primarily prove atomic file replacement rather than schema/data round trips.
      Existing Node project memory, metadata, and migration state can still be lost or misread by Rust.
      📍 `tests/persistence_migration.rs:11-35,114-126`, `tests/fixtures/persistence/legacy-empty.db`

- [ ] **[7] [P1] Distribution** — Native release automation cannot produce the documented release bundle
      Only Windows workflows are checked in, while smoke scripts require both aliases, signatures, SBOMs, and artifacts not generated by the release workflow.
      Linux/macOS installs and verifiable releases remain unproven.
      📍 `.github/workflows/windows-release.yml:31-65`, `scripts/release-smoke.sh:28-33`, `docs/release/platform-support.md:3-5`

## Features

- [ ] **[8] [P1] Gap** — Semantic AgentDB/RVF retrieval is not equivalent to Node
      Rust's deterministic hash-vector fallback and generic catalog path do not reproduce Node's embedding, hybrid retrieval, reranking, or metadata semantics.
      Search quality and semantic interoperability are unproven for existing projects.
      📍 `src/crates/ruflo-cli/src/embeddings.rs:10-69`, `src/crates/ruflo-cli/src/onnx_embed_stub.rs:1`, `src/crates/ruflo-mcp/src/tools_catalog.rs:138-162`

- [ ] **[9] [P1] Gap** — Native plugin lifecycle is incomplete
      Rust records plugin intent but does not provide Node-equivalent local/npm registry discovery, install, upgrade, or metadata workflows.
      Users cannot complete plugin lifecycle operations through the native CLI.
      📍 `src/crates/ruflo-cli/src/plugins.rs:83-176`, `/mnt/datadisk/dev/ruflo/v3/@claude-flow/cli/src/commands/plugins.ts:208-319`

- [ ] **[10] [P0] Feature** — Extract a stable shared Rust core API
      The current implementation is CLI-shaped: parsing, current-directory resolution, stdout, and dispatch are coupled in `ruflo-cli`.
      A shared core is required to avoid duplicating algorithms and to support CLI, MCP, and NAPI adapters consistently.
      📍 `src/bin/ruflo/src/main.rs:3-5`, `src/crates/ruflo-cli/src/lib.rs:204-218`

- [ ] **[11] [P0] Feature** — Build a real Ruflo NAPI-RS addon
      The workspace has no `napi`/`napi-derive` dependency, cdylib crate, Node loader, npm package, ABI tests, or addon benchmark.
      Node cannot consume Ruflo native core functions in-process, and no valid NAPI performance or distribution claim is possible.
      📍 `Cargo.toml:23-49`, `docs/benchmarks/node-vs-rust-methodology.md:34-44`

- [ ] **[12] [P1] Feature** — Ship NAPI and native binaries through a tested platform matrix
      The addon needs per-platform npm artifacts; native CLI releases need Linux, macOS, Windows aliases, checksums, signatures, SBOM, and install smokes.
      A distribution channel only exists when users can install and verify it on supported platforms.
      📍 `PRD.md:20-24,58`, `.github/workflows/windows-cross.yml`, `scripts/release-smoke.ps1:16-38`
